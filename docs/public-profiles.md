# Public neighbor profiles and avatars

Apply `supabase/migrations/202611020007_public_profiles.sql` after migrations 001–006, using the Supabase SQL editor or your migration runner. The application does not apply production SQL automatically. Existing account/profile text editing continues before this migration, with an initial-letter avatar. Public neighbor pages and photo uploads require 007.

The migration adds an owner-editable avatar path and a public `zuno-avatars` bucket. Photos are intentionally public, as the upload form explains. A constrained security-definer RPC projects only id, display name, neighborhood label and avatar path. It does not expose email, language, creation dates, private chats or the underlying profiles table. Public profile lists include at most 60 active listings, newest first; reserved, sold and removed items are excluded.

The upload API verifies the session and trusted site origin, bounds the multipart body, validates file length/type and decoded still-image format, and re-encodes WebP with EXIF/GPS removed. Unique paths and compare-and-set profile updates prevent simultaneous uploads from silently overwriting another completed update. Failed profile writes clean up the new file; successful replacements attempt deletion of the old file. A storage outage during cleanup may leave an unreferenced public file; no service-role key is used. Public image URLs may remain in browser/CDN caches after replacement. There is no avatar deletion feature in this change.

Shared Avatar renders initial-letter fallback or the photo. Settings includes an upload form and public-profile link. Account links the current profile name; live listing seller cards and conversation participant names link to `/neighbors/[id]`. Sample sellers keep demo behavior. Snapshot names on historical listings/chats are retained; the public page shows the current profile name.

Validation: lint, production build, 15 existing Node tests, and all disposable PGlite migration/RLS suites including new `supabase/tests/public-profiles.sql`. Browser/IAB control unavailable, so Playwright Chromium with an isolated local Auth/REST/Storage fixture verified upload, replacement, previous-file cleanup, failed-save cleanup, fake image rejection (400), public unauthenticated access, hidden email, listing profile link, and mobile overflow at 390×844. Screenshot was visually inspected with view_image. No real user records were changed. Real Supabase storage behavior still needs a smoke test after applying 007.
