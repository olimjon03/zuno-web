## Backup, restore and rollback procedure

Proposed operational procedure, not a completed recovery drill:

1. Before a schema rollout, record the deployed Git SHA and migration list.
   Confirm the actual project's backup/PITR availability and retention in the
   dashboard. Assign an owner and agree recovery point/time objectives.
2. Take an encrypted database backup using the supported Supabase backup/export
   workflow. Record backup time, integrity checksum and access controls.
3. Back up Storage object bytes separately through authenticated Storage tooling.
   Preserve bucket/name/content type and an object manifest with checksums. A
   database backup contains Storage metadata, not the underlying object bytes.
4. Restore into an isolated staging project. Restore database roles/schema/data
   according to Supabase's supported procedure, then restore object bytes.
   Configure staging Auth redirects and secrets separately.
5. Compare row counts, constraints, RLS, grants and object checksums. Run the SQL
   suite and staging browser flows: email/Google login, listing with photos,
   private chat attachment, profile edit and deletion of disposable accounts.
6. Record measured restore duration and data loss window. Approve production
   recovery only after staging validation and explicit operational authorization.
7. For an application regression, select the previous compatible release.
   Prefer a reviewed forward database fix. Do not drop columns/tables to reverse
   a migration while newer application instances can still write them.
8. For destructive data incidents, freeze affected writes, preserve evidence,
   select a verified backup and coordinate database plus Storage recovery.
   Validate references and access policies before reopening traffic.

Supabase backup reference:
https://supabase.com/docs/guides/platform/backups

## Running the new isolated SQL suite

Install the pinned test-only engine outside the app, then pass its module path:

    npm install --prefix /tmp/zuno-db-tests --no-save --ignore-scripts @electric-sql/pglite@0.5.14
    PGLITE_MODULE=/tmp/zuno-db-tests/node_modules/@electric-sql/pglite/dist/index.js node scripts/test-database.mjs

The fixture supplies minimal Auth/Storage tables for PostgreSQL behavior. It does
not run GoTrue, realtime delivery or the real Storage service. No production
credentials are needed. The application CI job uses npm ci, lint, tests and build.
