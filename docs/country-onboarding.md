# Country onboarding and regional marketplace

Apply migration `202611040016_country_onboarding.sql` after 015 before deploying this branch. It adds private profile country preference, district lookup data and codes, an owner-only country/neighborhood RPC, country-area consistency checks and a district-aware search RPC. Existing listing locations, IDs, photos, messages and prices are preserved. Duplicate locality names are permitted because district IDs distinguish them. See [location data attribution](location-data.md) for sources, corrections and CC BY licensing.

After password login, Google callback or signup confirmation, the session's confirmation cookie is cleared and the user goes to `/welcome`. They confirm Uzbekistan or Korea before proceeding. The page preselects their stored profile country on later logins. Country saving verifies the authenticated user, uses an atomic RPC, and writes a user-bound browser preference only after success. The proxy redirects authenticated users missing a matching confirmation cookie from home/account/messages/sell to welcome. API authorization remains independent of that preference cookie; no preference grants data access. Anonymous marketplace browsing remains available.

Country confirmation preserves an existing neighborhood when it belongs to the selected country, including existing profiles created before onboarding. A country switch clears the old neighborhood unless the same action supplies a valid neighborhood in the new country. Country/neighborhood changes never write display names, email or photos. Existing listings stay where they were posted, including their existing currency; changing personal country does not convert old prices. Region-only legacy listings remain in broad region results; a precise district cannot be inferred automatically, so a district filter includes only listings assigned to that district.

The welcome page has English / Uzbek / Korean / Russian. Uzbekistan marketplace has Uzbek / Russian / English. Korea has Korean / English / Uzbek / Vietnamese. An incompatible previous language falls back to English, while compatible selections persist. All existing interface dictionary entries have Russian and Vietnamese translations with placeholder checks. User-authored listings, names, messages and filenames are never translated. Proper locality names retain their source names (or English names for international display).

All nearby is region → district within the confirmed country. District filters use the same keyset pagination and are included in cursor fingerprints. New posts and profile area editing use region → district with no country selector. Change neighborhood permits country → region → district and updates the persisted marketplace country after a successful save. Existing listing edits keep their original country to avoid silently converting price currency.

Welcome UI follows the approved desktop/mobile reference with wordmark before the pin, country radios, local illustrations and a confirmation button. Native accessible select/radio controls support keyboard use; saving errors preserve selection and offer retry. No new packages or Next.js configuration changes.

Generated asset: `public/images/welcome-neighborhood.webp`, using the built-in image generation tool; prompt requested a wide teal/mint line illustration of two neighborhood houses linked by a location pin, with a white background and no text. Stored locally and optimized to WebP. Country landmark illustrations are code-native SVG.

Validation includes Node tests for preference parsing, country language menus, all translation placeholders, district parents and malformed/cross-country filters; database tests for country writes, identity isolation, same-country retention, clearing stale neighborhoods, invalid country/district denial, posting consistency and district search. Browser QA uses disposable synthetic auth/storage data rather than production accounts.
