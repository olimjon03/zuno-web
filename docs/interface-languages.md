# Interface languages

The homepage header offers Korean (🇰🇷 한국어), Uzbek (🇺🇿 O‘zbekcha), and English (🇬🇧 English). On desktop it sits between Messages and Sell; on mobile it is a compact flag selector immediately left of Account/Login. The account desktop header and the Language & appearance preference also expose the same selector. Themes and other planned features remain previews.

`src/features/language/catalog.ts` defines supported language codes. `messages.ts` contains reviewed Uzbek and Korean interface dictionaries using English source keys. `translate.ts` supports named placeholders without interpreting HTML. `provider.tsx` provides `Text`, `useT`, and a shared language selection. Text returns plain React text with no extra DOM wrapper, including inside native select options.

Selection updates mounted client and server-rendered interface labels immediately, without a network request, route refresh, or losing drafts. It is stored under `zuno.language` in localStorage and synchronizes across tabs. Invalid stored codes fall back to English. When storage is unavailable, a selection still works for the current tab. The HTML lang attribute tracks the selected language. Server-rendered HTML and metadata use English initially; a saved preference is applied after hydration. This avoids adding request-time cookie reads to otherwise cached routes. Unknown backend errors fall back to their original English message.

Coverage includes navigation, account and profile forms, categories and country/region controls, publishing and listing management, Saved, inbox and chat controls, safety/reporting, loading/error screens, and help content. User-authored listings, descriptions, names, messages, file names, and native neighborhood names remain original. Language never changes the chosen country, currency, filter keys, form values, or Supabase data. All supported regional labels in the country selectors are localized. Relative inbox dates use the selected language. So‘m grouping uses a consistent separator on server and browser to prevent ICU-version hydration differences.

For new UI copy, add a bilingual dictionary entry and render `<Text>{"English source"}</Text>` or use `const t = useT()` for input placeholders, accessible labels, and interpolated strings. Wrap only application-owned copy. Keep canonical category values, IDs, statuses, and search parameters untranslated. Named placeholders must match across all three languages.

Validation: lint, TypeScript, production build, 56 Node tests including translation placeholder/catalog checks, and isolated browser QA for desktop/mobile language selection, persistence after reload, translated login/account screens, language preference dialog, cross-tab updates, and preservation of a profile draft. No migration, environment variable, package, or Next.js configuration change is required. Hosted OAuth and production Supabase were not changed by QA.
