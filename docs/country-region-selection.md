# Country → region browsing

The All nearby control now starts with exactly two country choices, Uzbekistan and S. Korea. A region selector appears only after choosing one. Switching country clears the previous region. All regions includes the chosen country; All nearby removes location restrictions. Clear filters resets location, category and search. Shared client state survives normal app navigation and the homepage's sample-to-live streaming transition; it resets on a full browser reload. There is no geolocation or location-verification request.

Catalog sources:
- Uzbekistan e-government: https://my.gov.uz/ru/for-foreigners and regional list https://govinfo.uz/en/hokimiyats — twelve provinces plus Karakalpakstan and Tashkent city. The latter two appear in a separate group, rather than being mislabeled as provinces.
- Korean government: https://www.studyinkorea.go.kr/eng/life/regionsIntro.do and https://www.mois.go.kr/eng/sub/a03/citiesProvinces/screen.do — seventeen province-level units, including cities and the current Gangwon/Jeonbuk/Jeju special provinces. Cities and provinces are grouped separately.

Files: locations/catalog.ts owns the lists, validation, filtering and labels; LocationSelector renders native accessible selects; LocationProvider preserves selection; header/homepage integrate filtering; server listing mapping carries the existing neighborhoods.region_code into optional listing country/region metadata. Listing cards/details no longer hard-code Seoul for arbitrary locations.

Existing four seeded Seoul neighborhood names have a narrow legacy fallback when region_code is absent. Valid explicit metadata overrides that fallback. Unknown places are not guessed into either country. Future entries can use catalog region codes in the existing neighborhoods.region_code field; no schema change is required. This task does not add posting neighborhoods, translate prices/currencies, populate Uzbek listings or alter profile/selling forms. Filtering operates on the current feed (up to sixty live listings), not a new nationwide pagination/search API. Empty regions show the normal empty state, never invented listings.

Validation: lint, production build, and twenty Node tests, including country isolation, all-region coverage, reset validation and non-Seoul labels. Playwright Chromium fallback (Browser/IAB automation unavailable) checked country-first rendering, twelve Uzbek provinces/fourteen total units, seventeen Korean units, switching/reset, Seoul vs Busan vs Uzbekistan results, search combination, client-navigation persistence and overflow at 320/390/680/768/1024/1440px. Mobile and desktop screenshots were inspected with view_image. Test writes did not touch real user records. Existing unrelated working-tree changes remain separate.
